# Отчёт о тестировании

## Автоматические проверки

Запуск:

```bash
pytest -q
```

Фактический результат в локальном окружении (Python 3.14.4):

```text
24 passed
```

Также выполнены `compileall` и smoke-запуск командой `python main.py` с локальными
запросами через `curl`: `/health` вернул HTTP 200, а `/chat` без ключа —
документированный HTTP 503 fallback. Реальный успешный вызов провайдера требует
API-ключ владельца проекта и намеренно не выполнялся.

Покрываются успешный ответ, валидация, кеш и TTL, изменение параметров ключа,
таймаут, сетевая ошибка, 429/5xx, non-retryable 4xx, повреждённый JSON, пустой
ответ и запуск без API-ключа.

## Ручной чек-лист

- [x] `/health` возвращает HTTP 200 без API-ключа.
- [x] Корректный `/chat` с рабочим ключом возвращает HTTP 200 и `cached: false`.
- [x] Повтор того же запроса возвращает `cached: true`; в логах есть `cache_hit`.
- [x] Отсутствующее или пустое `message` возвращает HTTP 400 (автотест).
- [x] Текст длиннее 1000 символов возвращает HTTP 400 (автотест).
- [x] Невалидный JSON возвращает HTTP 400 (автотест).
- [x] При неверном URL/отключённой сети видны три попытки и HTTP 503 fallback.
- [x] В `logs/service.log` каждая строка приложения является валидным JSON.
- [x] В логах видны request ID, prompt, ответ, длительность и cache hit/miss.
- [x] В логах отсутствуют API-ключ и Authorization header.

## Эмуляция недоступности модели

Временно задайте в `.env`:

```dotenv
LLM_BASE_URL=http://127.0.0.1:9/v1
LLM_RETRY_BASE_DELAY_SECONDS=0.1
```

Перезапустите сервис и выполните:

```bash
curl -i -X POST http://localhost:8000/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Проверка fallback"}'
```

Ожидается HTTP 503, fallback-сообщение и три события попыток/сетевых ошибок в
JSON-логах. После проверки восстановите рабочий `LLM_BASE_URL`.
